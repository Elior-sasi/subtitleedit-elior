# יישור תסריט לשמע בענן - Montreal Forced Aligner 3.4.3

השירות ב־`service/` הוא API אסינכרוני סביב ה־CLI הרשמי של MFA. בתוכנה הוא נפתח מתוך
"פרויקט ← תסריט לכתוביות ← יישור בענן עם MFA". מנוע CrispASR המקומי לא השתנה ונשאר ברירת המחדל.
מבנה ה־API והתוצאה: [service/API.md](service/API.md).

## עברית - מצב בפועל (נבדק 2026-10-25)

בקטלוג הרשמי של MFA ([מודלים אקוסטיים](https://mfa-models.readthedocs.io/en/latest/acoustic/index.html),
[מילונים](https://mfa-models.readthedocs.io/en/latest/dictionary/index.html),
[G2P](https://mfa-models.readthedocs.io/en/latest/g2p/index.html)) **אין לעברית מודל אקוסטי, מילון הגייה או G2P**.
לכן השירות מציג את העברית כ"לא זמינה" עם הסבר, ולא מיישר עברית במנוע אחר.

מה נדרש כדי להוסיף עברית:
1. קורפוס הקלטות עבריות עם תמלול מדויק ורישיון שמתיר אימון (עשרות שעות לפחות).
2. מילון הגייה: כתיב עברי בלי ניקוד אינו מגדיר הגייה, ולכן נדרשים מילון מנוקד או G2P לעברית.
3. אימון ובדיקה עם `mfa train` ו־`mfa validate`, ואז הוספת רשומה ל־`service/deploy/models.json` עם גיבובי SHA-256.

## מה נבדק בפועל ומה לא

- **אנגלית, דיבור אמיתי** (דגימות LibriSpeech ו־Common Voice מתוך מאגר הבדיקות של MFA): 5 הקלטות שחוברו עם שקטים ידועים (95 שניות).
  גבולות הכתוביות תאמו ליישור נפרד של כל הקלטה בטווח של כ־10ms, חוץ ממילת מילוי אחת של 30ms ("uh").
- יישור במעבר אחד על אודיו ארוך נכשל (`NoAlignmentsError`), או הסיט כתובית ב־3.5 שניות. לכן השירות עובד בשני מעברים.
- **תסריט חסר מילים**: MFA "מצליח" ומחזיר זמנים שגויים (סטייה של 20 שניות). השירות מסמן זאת `needs_review`
  לפי הפסקה ארוכה שזוהתה בתוך הכתובית, אבל היעדר סימון אינו הוכחה לנכונות.
- **שמע שקט**: נכשל במפורש (`no_speech`).
- **לא נבדק**: שמע סרטים עם מוזיקה, רעש או דוברים חופפים, ועברית (אין מודל).
- תמונת ה־Docker לא נבנתה כאן, כי Docker Hub חסום בסביבת הבדיקה. אותה סביבת conda (MFA 3.4.3) והמודלים עם אותם גיבובים נבדקו ישירות.

## הקמה (בחשבון Google Cloud שלך, אחרי אישורך)

1. פתח [Cloud Shell](https://shell.cloud.google.com/) בפרויקט ייעודי שהחיוב בו כבר פעיל.
2. העתק אליו רק את התיקייה `cloud-mfa/service`.
3. צור אסימון למשתמש: `python3 -m mfa_service.admin elior > tokens.json`. האסימון מודפס פעם אחת - שמור אותו להדבקה בתוכנה.
4. הצג תוכנית והערכת עלות, בלי שום שינוי: `bash deploy/deploy.sh PROJECT_ID --plan`
5. פרוס, עם אישור באמצעות הקלדת מזהה הפרויקט: `bash deploy/deploy.sh PROJECT_ID --deploy tokens.json`
6. בדוק בריאות: `curl -fsS https://…run.app/healthz`
7. בתוכנה: הדבק את כתובת השירות ואת האסימון ולחץ "שמור חיבור ובדוק שפות זמינות".

הערכת עלות: כ־0.19 דולר לשעת מופע פעיל (2 vCPU, 8GiB), כולל עד כ־15 דקות המתנה לפני כיבוי.
המכסה החינמית החודשית מכסה כ־15 שעות מופע. בנוסף: Cloud Build ואחסון התמונה (כ־3GB).
זו הערכה ולא תקרת הוצאה. הסקריפט לא משנה חיוב ולא יוצר מפתחות של חשבון שירות.

## תפעול

- יומנים: Cloud Run ← השירות ← Logs. נרשמים רק מזהי משימות, גדלים, משכים וקודי שגיאה.
- החלפת אסימונים: צור `tokens.json` חדש והרץ שוב את שלב 5 (נוצרת גרסת סוד חדשה, והשירות טוען אותה מחדש).
- מחיקה: השמע והטקסט נמחקים בסיום כל משימה, והתוצאה בייבוא, בסגירת החלון או אחרי 6 שעות. דלי האחסון מוחק כל קובץ אחרי יום.
- מופע אחד, יישור אחד בכל פעם: משימות נוספות ממתינות בתור (עד 10, ועד 2 פעילות למשתמש).
- הסרה מלאה: מחק את שירות Cloud Run, הדלי, הסוד ומאגר התמונות במסוף.

## בדיקות

```bash
python3 -m unittest discover -s service/tests -t service -p 'test_*.py'   # שירות, אבטחה, שמירה, פריסה (מנוע מדומה)
MFA_REAL_MODELS=models.json MFA_REAL_WAV=a.wav MFA_REAL_CUES=cues.json \
  python3 -m unittest service.tests.test_service.RealEngineTests          # MFA אמיתי
python3 -m unittest discover -s . -p 'test_setup.py'                      # בדיקת ההתקנה הקודמת (probe)
```

`setup.sh`, `probe.py` ו־`Dockerfile` בתיקייה הזו הם בדיקת ההתקנה הקודמת (CLI בלבד), ונשמרו ללא שינוי.
